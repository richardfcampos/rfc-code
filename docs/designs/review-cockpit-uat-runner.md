## Problem (user's words, translated)

Tasks already arrive in "review", but there is nowhere to decide how to proceed:
no place to talk to the agent, no data from the AI to base the decision on, no
signal whether only UAT remains. If UAT is needed: a button to run the app
locally and get a `vps:port` URL to test. If not: pass straight to done. If a
change is requested during review, the task must go back to in-progress and
return to review when the agent finishes.

## Vision

### 10x Check
Cross-project "decision inbox": every agent task awaiting a human decision on one
screen, each with evidence (AI brief, diff, UAT checklist) and one-tap
approve / request-changes / test. Audit trail of every decision. Review SLAs
(stale-review indicators). "Manager of agents" UX — human time goes only where
judgment is needed. This plan's artifact store + preview runner are the substrate;
nothing in the accepted scope blocks the inbox later.

### Platform potential
- Run-artifact store → reusable by design-review / retro / notification flows.
- Preview runner ("boot this project's app, give me a URL") → reusable by
  canary, benchmark, browser-QA flows.

## Chosen approach

APPROACH B — "Review cockpit" (of A: visibility+buttons / B: full cockpit /
C: cockpit without persistence). Chosen for completeness: persisted evidence
survives transcript churn; UAT runner is the explicitly requested piece.

## State machine (core loop, user-confirmed)

```
                 run completes (linked task)
  in-progress ────────────────────────────────▶ review
      ▲                                           │
      │  Request changes (+feedback text →        │ Approve
      │  message sent to linked session run)      ├────────▶ done ──(optional)──▶ merged
      └───────────────────────────────────────────┤
                                                  │ Run UAT
                                                  └────────▶ review (preview up,
                                                             decision still pending)
```
Loop repeats until Approve. Each round persists a new run artifact → timeline.

Semantics:
- **"Clean run completion"** = `complete` event received for the run AND no
  `session_run_failures` row persisted for it AND the run was not cancelled/
  interrupted. Anything else does NOT produce an artifact-of-record.
- **Arrival into review is AGENT-DRIVEN (revised after outside-voice review).**
  A run "complete" = one prompt→response turn, NOT "task finished" — so the
  server never moves tasks to review on its own. The agent keeps setting
  `review` via task-master (works today). The server's job is the EVIDENCE
  GUARANTEE: persist an artifact on every clean completion of a linked session,
  and detect status→review changes to fire badge + notification. Zero
  wrong-card moves by construction.
- **Request changes** = start a NEW run on the linked session (provider resume)
  with the feedback text as the prompt. If multiple sessions link to the task,
  feedback goes to the session that produced the latest run artifact for it.
  The cockpit only dispatches feedback; back-and-forth conversation happens in
  the linked session's chat view.
- **Preview lifecycle:** Approve stops the preview process; Request changes
  leaves it running (user may re-test next round) subject to idle cleanup.

## Implementation decisions (resolved now, not mid-build)

- **Task↔session linkage: EXPLICIT.** Task id attached when a run starts — UI
  "work on this task" action + env var visible to the agent. No heuristics, no
  wrong-card moves. **Storage:** `linked_task_id` (+ project id) column on the
  sessions table, set by the UI action at run start; copied onto each run
  artifact at completion. Available at run start (env var) and at run complete
  (auto-transition) before any artifact exists.
- **UAT URL: raw `vps:port`.** Tailnet is the trust boundary (matches existing
  deployment posture). **Bind is engineered, not assumed:** dev servers default
  to 127.0.0.1, so the per-project run config includes bind host, and the runner
  injects it (`HOST`/`--host`, framework-aware via auto-detect) along with the
  port. Note: `assertTrustedModeBindIsSafe` governs only the rfc-code server
  process; preview processes are separate and governed by the tailnet boundary.
- **Port detection: assigned, not scraped.** The runner allocates a free port and
  injects it via `PORT`/`--port` per the run config, then polls the port until it
  listens (with timeout). Stdout-regex scraping is a fallback only for commands
  that ignore port injection. (The plugin-process-manager precedent's JSON
  ready-line protocol does NOT transfer to arbitrary dev servers — its lifecycle
  discipline does.)
- **Run command source: per-project config in rfc-code DB, editable in UI,
  pre-filled by auto-detect** (package.json scripts / framework detection) on
  first use. Config fields: command, port strategy, bind host. Runs in the
  task's worktree.

## Accepted Scope (baseline + accepted expansions)

1. Review kanban column + i18n keys (fixes vanishing-task bug).
2. `session_run_artifacts` persistence at run-complete: final assistant message,
   diff stat, changed files, linked task id, timestamps.
3. Explicit task↔session linkage (UI action + env var).
4. Review cockpit panel on review cards: AI brief, raw final message, diff viewer
   (reuse GitDiffViewer), UAT checklist, decision actions:
   - **Approve** → done (+ optional squash-merge with confirm)
   - **Request changes** → feedback text → message to linked session → task →
     in-progress; returns to review on next clean run completion
   - **Run UAT** → start preview → show `vps:port` URL + copy button → stop button
5. UAT runner service (plugin-process-manager pattern): spawn per-project run
   command in worktree, port detection, lifecycle tracking, idle cleanup.
6. Review-arrival detection: server watches task status changes to `review`
   (agent-driven), fires badge + notification (`TASK_REVIEW_READY`). No
   server-initiated status moves.
7. Review inbox badge.
8. AI review brief generation (generate-commit-message pattern).
9. Artifact history timeline per task.
10. Polish (delight, in scope): diff-stat chips on review cards; copy-URL button;
    stale-review indicator (>24h); badge count on tasks tab.
11. Cross-project Decision Inbox (user upgraded from TODO to scope): single
    screen listing every task awaiting decision across projects, opens cockpit.
    Builds directly on artifacts + badge substrate.
12. Automated UAT (user upgraded from TODO to scope): browser-use (existing
    `server/modules/browser-use/`) executes the AI-generated UAT checklist
    against the preview URL; result attached to the run artifact. Human UAT
    remains the final gate — automation is evidence, not approval.
13. Frontend test runner (user upgraded from TODO to scope, refined after
    outside voice): **vitest for frontend only** (jsdom, cockpit state logic,
    inbox filtering, badge counts); node:test + tsx remains owner of server
    tests. Fix existing npm-test glob gap (`.test.tsx` files not picked up).

## Outside-voice hardening (applied fixes)

- **Linkage lifecycle:** link set/cleared by the "work on this task" UI action;
  artifact captures task ref at RUN START (not session-current at completion);
  cockpit shows current link with a clear/unlink control. Stale links cannot
  attribute later unrelated runs.
- **Task ref = tag + id** (task-master ids are tag-scoped and renumberable;
  server currently hardcodes the `master` tag — store both, accept residual
  instability as single-user risk).
- **Worktree bootstrap:** preview run config gains optional `setup command`
  (e.g. `npm install`) run once per worktree before first boot, and an env
  strategy (copy/symlink `.env` from the main checkout). Without this, fresh
  worktrees can't boot most apps.
- **Busy/dead session on Request changes:** active run on linked session →
  button disabled ("agent still working"); session/transcript gone → start a
  fresh session in the same worktree with the feedback as prompt.
- **Diff base:** artifact stores base SHA (merge-base with the worktree's base
  branch at run start). Timeline shows per-round incremental diff + cumulative
  toggle. Sessions without a worktree (shared checkout) get diff-stat marked
  "partial — shared checkout".
- **Preview ephemerality:** previews do not survive rfc-code restart/deploy —
  by design. Startup sweep kills orphans; cockpit shows "preview stopped
  (server restarted)" with one-click re-run.
- **Bind mechanism named:** previews bind to the tailscale interface IP
  (resolved at spawn), NEVER 0.0.0.0 (VPS has a public IP). App refuses
  IP-specific bind → clear error, no insecure fallback.
- **No-op rounds:** clean completion with empty diff renders a "no code
  changes this round" label in the timeline (agent asked a question / analysis
  only) — distinguishable from fix rounds.
- **AI brief cost:** generated lazily on first cockpit open, cached in the
  artifact row; input = final assistant message + diff (never full transcript).
  Automated UAT (item 12) is best-effort evidence, never a gate, and its
  browser-use runs are bounded per round.

## Cockpit & Inbox UI spec (/plan-design-review 2026-08-28)

All tokens/roles reference `plans/design-refresh/design-spec.md` ("Precision
Instrument"). Design-target viewport: **tablet 834px** (primary review device),
then desktop 1440. Classification: APP UI — calm surface hierarchy, utility
language, no decorative cards.

### Container (user decision)
**Full-height right-side drawer** (`--scrim` backdrop, `--shadow-float`,
tablet drawer behavior per spec §5). Opened from review card AND from Decision
Inbox rows — one component, two entry points. Review card itself only gains
diff-stat chips + stale dot; never expands in place. Card-in-card nesting
forbidden; inbox is rows, not cards.

### Cockpit hierarchy (top → bottom)
1. **Anchor:** task title + brief verdict header — "what changed / risks /
   UAT-only?" (`.eyebrow` section headers, sans 13px body).
2. **Decision bar — sticky** (bottom on tablet, 44px min touch targets):
   - Approve: solid `--success` (squash-merge opt-in lives INSIDE the Approve
     confirm dialog, never a loose checkbox; merge only offered when linked
     session has a worktree).
   - Request changes: outline `--danger-line` (rejection ≠ destruction; not
     solid red). Disabled with "agent still working" when a run is active.
   - Run UAT is NOT in this bar (tier 2, lives with the checklist).
3. **Evidence (collapsed by default):** UAT checklist → diff (stat chips
   expanded, full diff on demand via GitDiffViewer) → raw final message
   (collapsed details, mono — fallback evidence, never outranks the brief) →
   round timeline ("Round 3 · +42 −7 · 2 files"; incremental default,
   cumulative toggle in timeline header; empty-diff rounds labeled "no code
   changes this round").

### UAT block
- Boot state machine visible: `Installing deps… → Starting… (Ns) → ● Ready —
  vps:41234`, live log tail collapsed (mono, `--surface-2`), Cancel always
  available. Distinct failures with next action: setup failed (log), port
  timeout (log + edit run config), bind refused (copy: "App couldn't bind to
  the tailnet address — check run config").
- Ready state: **"Open preview" primary** (new tab, same device — one tap on
  tablet), copy URL secondary, **QR code** for desktop→tablet hand-off. URL
  rendered large, mono — it is the payoff artifact.
- Automated UAT results (item 12) render as per-item annotations on the SAME
  checklist (✓/✗ dot in `--success`/`--danger` + note), visually subordinate
  to the human checkbox — automation is evidence, not approval.

### Interaction states
| Feature | LOADING | EMPTY | ERROR | SUCCESS | PARTIAL |
|---|---|---|---|---|---|
| AI brief | skeleton on brief block only; evidence renders immediately; decisions NEVER blocked | — | inline row + retry; raw msg auto-expands | brief header | "partial evidence" chip (transcript unreadable) |
| Cockpit evidence | drawer opens instantly from artifact | "No run evidence for this task" + link-a-session affordance; decisions still enabled (day-one state for pre-existing tasks; badge still fires) | diff unavailable warning chip | full evidence | "partial — shared checkout" badge |
| Preview | boot machine above | — | per-failure states above; "preview stopped (server restarted)" + one-click re-run | ● Ready + URL | crashed mid-UAT: status flips + log kept |
| Approve+merge | progress on button | — | conflict: task STAYS in review; drawer lists conflict files + "resolve in session"; approve-sans-merge never blocked by merge state | card animates out of column | — |
| Request changes | sending state | — | toast with reason; feedback text preserved | drawer becomes read-only tracker: "Round N enviado · agente trabalhando" + jump-to-session link (user closes when done) | — |
| Review column | — | quiet empty (no illustration circus) | — | — | — |
| Inbox | row skeletons | **Inbox zero = reward state**: "Nada aguardando decisão" + subtle ✓ (design deliberately) | — | — | — |
| Badge | — | hidden at 0 | — | count, cap "9+" | — |

All state copy via i18n keys (item 1 already opens the locale files).

### Decision Inbox anatomy
Rows grouped by project (`.eyebrow` mono 10px 0.08em `--faint` group headers).
Row = task title (sans 13px) + diff-stat chips (mono `.micro`) + age (mono
11px `--muted`) + stale dot (>24h, `--warning`). Sort: stale-first, then
oldest-first. Mount: cross-project home in the sidebar (badge total lives
there; per-project badge stays on tasks tab). Row tap → same drawer.

### Motion (3 earned moments, spec §6 timings)
Badge increment tick; card exit on approve; boot-state transitions. Nothing
else moves.

### Accessibility
Keyboard: drawer focus-trap, Esc closes (not while merge in flight), a/r/u
shortcuts for Approve/Request/UAT (delight item). ARIA: badge
`aria-label="N tasks awaiting review"`; boot machine `aria-live=polite`.
Contrast: amber/`--warning` stale indicators checked against `--surface` per
token spec; decision buttons rely on label+color, never color alone.
Shadows: only `--shadow-float`/`--shadow-pop` on drawer/popover — no chip or
card shadows.
